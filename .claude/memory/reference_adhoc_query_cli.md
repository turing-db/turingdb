To run an arbitrary Cypher query against simpledb through the v3 engine without a server:
drop a JSON test into `test/query-test-suite/tests/` (the directory is compiled in as
`QUERY_TEST_SUITE_DIR`, so the file must be in the source tree) and run it by file stem:

    {"enabled": true, "graph": "simpledb", "query": "MATCH (a)-->(b)--(a) RETURN count(*)",
     "expect": {"result": ""}, "tags": ["probe"], "write-required": false}

    ./build/test/query-test-suite/query_test_suite_cli --run <stem>

The JSON result carries `resultOutput` (the rows) and `mlirProgram` (the db-dialect program
after passes), so it shows which ops a query compiles to. `--list` lists every test.

Two things to clean up: delete the probe files afterwards, and the CLI writes a scratch
directory `query_test_suite_cli/<test>/data/` into the current directory for every test it
runs, which lands untracked in the repo root - `rm -rf query_test_suite_cli`.

The suite's `expect` values were generated by v2, which matched homomorphically, so an
oracle is not proof of Cypher semantics: `fuzz-undirected-cycle-merge` expects 22 rows for
`(a)-->(b)--(a)` where relationship isomorphism gives 4. See [[reference_regress_runs_v3]].
