A suite fixture in `test/query-test-suite/tests/<name>.json` carries `expect.result` (the
rows as `query_test_suite_cli --run <name>` prints them in `resultOutput`) and, for most
fixtures, `expect.resultJson`: `{"header":{column_names,column_types},"data":[[col1,...]]}`,
one list per column inside one chunk, `[[[]]]` for an empty one-column result. To
regenerate: run the CLI, paste `resultOutput` into `result`, and rebuild `data` from the
rows under the unchanged header (ints for UInt64/Int64, strings otherwise). Keep the
file's own indentation: most use 2 spaces, some (`variable-length-paths-*`) 4.

**Why:** the 394 oracles were generated by v2, which matched homomorphically. Step 1 of
`docs/edge_uniqueness/PLAN.md` regenerated 14; ten more with comma patterns joined on one
node (`success-reads-loop-*`, `success-reads-match-where-*`, `successor-join-then-filter`,
`value-hash-join-where-2`, `variable-length-paths-7`) stayed homomorphic until 2026-09-30.
Any remaining oracle with two or more edges in one clause is still suspect.

**How to apply:** before overwriting, check the new count against an independent
enumeration of simpledb under relationship isomorphism (a Python script over the 18 edges;
node IDs in [[feedback_test_on_simpledb]]). See [[reference_adhoc_query_cli]] for the CLI.
